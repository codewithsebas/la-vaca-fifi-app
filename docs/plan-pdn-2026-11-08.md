# Plan para PDN: 8 de noviembre

Sube a PDN (`main`, lavacafifi.com) lo que ya está en QA (`develop`, `f7f3bf4`). Ningún paso se ejecuta sin autorización.

## Qué sube

- Completar los datos de una reserva de Booking y enlazarla a su noche.
- Cambiar de cabaña una reserva, con las mismas fechas y el mismo valor.
- Tema del panel fijo, sin el editor de colores del panel.
- Pagos, Clientes, Bloqueos y baños, Empleados, Tarifas, Finanzas y Dashboard con su nuevo diseño.
- Sin variables de entorno ni dependencias nuevas.

## Objetos afectados en la base de PDN

| Migración                                   | Qué hace                                                                                                                                                                                                                                  | Destructiva                          | Datos que toca                              |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ------------------------------------------- |
| `20261108010000_cambio_de_cabana_y_booking` | Columna `channel_stays.reservation_code` (vacía), índice, `free_unit` y `bump_unpaid_after_channel_stay` actualizadas, función `complete_channel_stay`, disparador `reservations_stay_change`, dos tipos más en la comprobación de avisos | No                                   | Ninguna fila cambia                         |
| `20261108000000_quitar_colores_del_panel`   | Borra la clave `panel` de `site_settings.theme`                                                                                                                                                                                           | Sí, solo esa clave (se guarda abajo) | Una fila; los colores del sitio no se tocan |

No toca `reservations`, pagos, clientes ni cabañas. No manda correos ni push: ninguna reserva cambia de estado.

## Por qué en este orden

La versión nueva consulta `channel_stays.reservation_code`: sin la columna, la disponibilidad falla. La versión actual ignora esa columna, así que la migración de Booking puede ir **antes** del código sin afectar a nadie.

Con los colores es al revés: la versión actual pintaría el panel con el tema negro si falta `theme.panel`. Esa migración va **después** del código.

## Pasos

### 0. Inventario, solo lectura (necesita el CLI con la cuenta de PDN)

```sql
select version from supabase_migrations.schema_migrations order by version desc limit 1; -- debe ser 20261107000000
select status, count(*) from public.reservations group by 1 order by 1;
select count(*) filter (where removed_at is null) activas, count(*) total from public.channel_stays;
select theme -> 'panel' from public.site_settings; -- debe coincidir con el valor de la sección «Si algo sale mal»
select kind, count(*) from public.admin_notifications
where kind not in ('reservation_created','reservation_confirmed','reservation_cancelled','reservation_expired',
  'proof_uploaded','proof_approved','proof_rejected','payment_declined','payment_refund','balance_paid','balance_overdue','email_failed',

group by 1; -- debe salir vacío: si no, la comprobación de avisos fallaría y la migración se deshace sola
```

| Falla en         | Qué hacer                                                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Paso 2           | La transacción se deshace sola; nada cambió. Se detiene el plan.                                                                                         |
| Paso 3           | Revertir el merge en `main` y push: Hostinger publica la versión anterior. La migración de Booking puede quedarse, porque la versión anterior la ignora. |
| Paso 4 o después | Si se vuelve a la versión anterior, restaurar los colores con el SQL de abajo para evitar el tema negro.                                                 |

## A tener en cuenta

- Mientras Hostinger publica (unos 2 minutos) puede haber un momento de transición.
- Quien tenga el panel abierto debe recargar. Si un dispositivo guardó un cambio de colores sin enviar, aparecerá «por revisar» y se descarta.
- Las reservas importadas de Ayenda no llevan el indicativo azul: solo las que se completen desde una noche de Booking.
- Las noches de Booking sin datos, reservas o cierres, se ven como «Nueva reserva en Booking» hasta completarlas.
